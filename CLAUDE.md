# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

FPGA design (SystemVerilog / Verilog) for a Tang Nano 9K (Gowin GW1NR-9C, `GW1NR-LV9QN88PC6/I5`) that captures video from an OV7670 camera and renders it to a 4.3" LCD in real time, with on-the-fly resizing to preserve aspect ratio (vertical downscale + horizontal pillarbox downscale with black side borders). Frames are 640x480 RGB565 buffered in external PSRAM via a 3-frame circular buffer. Frame geometry (input/screen size, emit row size) is defined in `platform.json` at the repo root; CMake generates `src/platform_config.vh` from it at configure time.

## Repository layout

- `src/` — synthesizable RTL. The Gowin IP cores (`gowin_rpll`, `gowin_sdpb`, `gowin_sdpb_dn`, `gowin_alu54`, `fifo_top`, `psram_memory_interface_hs_2ch`, `sdpb_1kx32`, `cam_settings_rom`) are generated by Gowin IDE — regenerate them through the IDE rather than hand-editing the `.v`/`.vo` outputs.
- `src/fsms/` — `FrameUploader.sv` (camera → PSRAM; uploads pixel data INTO memory) and `FrameDownloader.sv` (PSRAM → LCD; downloads pixel data OUT of memory) state machines. The direction names follow the memory's perspective — easy to flip mentally; double-check the port list before wiring tests. `FrameDownloader` delegates the PSRAM reads + two ping-pong row banks to `src/DownloadRowCache.sv`.
- `platform.json` — single source of truth for the platform constants, grouped into four sections: `geometry` (input/screen size, emit row size), `clock` (`sys_clk_hz`), `modbus` (`device_id`, `addr_limit`, `max_read_qty`, plus the gateware-internal sizing `max_frame`/`reg_count`), and `uart` (`baud`, `data_bits`, `parity`, `stop_bits`). CMake parses it (a regex matches each key at any nesting depth, so the section names are cosmetic and keys must stay globally unique) and generates `src/platform_config.vh` (the `src/platform_config.vh.in` template, `.gprj`-listed and committed) with `` `PLATFORM_* `` macros. `VGA_timing.v` consumes the geometry macros; `camera_control.v` feeds the clock/modbus/uart macros to `uart`, `modbus_rtu_slave`, `modbus_cam_backend` (`UPTIME_DIV`), `i2c_control_fsm` and `device_delay` (`MAIN_CLOCK_FREQUENCY`). Edit the JSON, not the generated header. The UART framing (`data_bits`/`parity`/`stop_bits`) is fixed at 8-E-1 by the `uart.sv` FSM — those macros flow in as parameters and are checked against 8-E-1 at elaboration (`` `ifdef __ICARUS__ ``) rather than re-shaping the framing. The **host side reads the same `platform.json`** through `platform_config.py` (repo root): `webapp/modbus_client.py` (`DEFAULT_BAUD`/`DEFAULT_SLAVE` + framing) and the `scripts/modbus_test.py` / `scripts/frame_grab.py` CLIs default their baud/slave/parity from it, so gateware and host can't drift.
- `sim/` — Icarus Verilog testbenches, structured as `sim/common/` (shared infra and behavioural models — `svlogger.sv`, `test_utils.sv`, `psram_model.sv`, `i2c_slave_model.sv`, `test_config.sv.in`, the `run_simulator.{sh,bat}.in` wrappers), `sim/unit/<dut>/<scenario>.sv` for per-module tests, and `sim/integration/<topic>/<scenario>.sv` for cross-module tests.
- `FPGADesignElements/` — git submodule (laforest/FPGADesignElements) for CDC/pipeline primitives. Clone with `--recurse-submodules`.
- `scripts/scaler_generator.py` — generates lookup tables for `PositionScaler_horz.sv` / `PositionScaler_vert.sv`.
- `scripts/gw_run.sh` + `scripts/gw_run.tcl` — wrap Gowin's `gw_sh` Tcl console so the `hw_*` CMake targets can run synthesis / PnR / bitstream without the IDE GUI.
- `physical/` — OpenSCAD + STL for the 3D-printed enclosure.
- `doc/` — human-facing docs (`build.md`, `architecture.md`, `testing.md`, plus diagrams under `doc/images/`).
- `camera_ov7670.gprj` — Gowin IDE project file (authoritative list of enabled synthesis sources and constraint files).

## Build and test

Everything (bitstream + simulation + programming) is driven from the top-level CMake. Full reference lives in [`doc/build.md`](doc/build.md); the testing-specific reference lives in [`doc/testing.md`](doc/testing.md). Quick orientation:

**Bitstream / programming targets** (`scripts/gw_run.sh` wraps `gw_sh`, picks the LD_LIBRARY_PATH / LD_PRELOAD env the Linux launcher needs):

- `hw_synth` — synthesis only.
- `hw_impl` — place-and-route + bitstream → `impl/pnr/camera_ov7670.fs`.
- `hw_all` — both.
- `hw_program` — `programmer_cli -r 2` (SRAM, volatile).
- `hw_program_flash` — `programmer_cli -r 6` (embFlash, persistent).

The Gowin IDE GUI is still a valid fallback — `camera_ov7670.gprj` remains the authoritative source list for synthesis.

**Simulation tests** are CMake-driven and run on both Windows and POSIX. `sim/CMakeLists.txt` picks the per-test wrapper based on `WIN32` — `run_simulator.bat.in` on Windows, `run_simulator.sh.in` on Linux/macOS — and on non-Windows invokes the generated wrapper through `sh` (no executable bit needed, keeps the project compatible with `cmake_minimum_required(3.8)`).

Configure:

```
# Linux/macOS
cmake -S . -B build -D IVerilog_PATH=/usr/bin -D Gowin_PATH=/opt/gowin/IDE [-D DUMP_SIM_VARIABLES=ON]
# Windows
cmake -S . -B build -D IVerilog_PATH=<iverilog\bin> -D Gowin_PATH=<Gowin install root> [-D DUMP_SIM_VARIABLES=ON]
```

`Gowin_PATH` is required on every platform — CMake locates `simlib/gw1n/prim_tsim.v` and the `GowinSynthesis` binary under it, so you need a Linux Gowin EDA install (not just iverilog) to run tests on Linux. `DUMP_SIM_VARIABLES=ON` produces `dump.vcd` per test under `<build>/sim/tests/<scope>/<dut>/<scenario>/` for GtkWave. Log verbosity is `-D SimLogLevel=Fatal|Error|Info|Debug|None` (default `Info`), which sets `SVL_VERBOSE_*` in the generated `test_config.sv`.

Tests are registered through two lists in `sim/CMakeLists.txt`:

- `UNIT_TESTS` — entries of the form `<dut>/<scenario>`, sources at `sim/unit/<dut>/<scenario>.sv`.
- `INTEGRATION_TESTS` — entries of the form `<topic>/<scenario>`, sources at `sim/integration/<topic>/<scenario>.sv`.

Each entry expands (via the `register_test` function) to three CMake targets — `<scope>_<flat_name>_BUILD`, `_SIM`, `_run` — and gets ctest labels `<scope>` plus the DUT/topic name, so `ctest -L unit`, `ctest -L integration`, or `ctest -L buffer_controller` all filter sensibly. The `flat_name` is the slashed path with `/` → `_`. Run a single test with `ctest -R <flat_name>_run -V` or `make <scope>_<flat_name>_SIM`.

When adding a new platform wrapper, keep `sim/common/run_simulator.bat.in` and `sim/common/run_simulator.sh.in` in sync; both consume `@VERILOG_SIM@` and `@TEST_OUTPUT_FILE@` and redirect output to `output.txt` in the per-test working directory.

**Formal verification** — the self-contained single-clock control modules (`wb_interconnect`, `arbiter`, `watchdog`, `wb_sysregs`, `wb_osd`, `wb_grab`) carry property proofs behind `` `ifdef FORMAL `` in the RTL, proven by yosys's built-in SAT engine (no external solver). Run with `ctest -L formal` (targets are gated on `yosys` being found). The `.sby` files, `register_formal` registration, and the per-module property table live in [`sby/`](sby/README.md); the SAT-vs-SMT rationale is documented there.

## Architecture

Three clock domains generated by the Gowin rPLL (`src/gowin_rpll/memory_rpll.v`):

- **27 MHz** — system / camera XCLK / I2C-side logic.
- **135 MHz** — PSRAM controller and HyperRAM interface.
- **67.5 MHz** — buffer/arbiter logic (half of memory clock).
- **13.5 MHz** — LCD pixel clock.

Crossings between these domains use the `CDC_*` and `Pulse_*`/`Pipeline_*` primitives from `FPGADesignElements/` — re-use those rather than rolling new synchronizers.

Data path:

1. `i2c_control_fsm` + `i2c_master*` push the register map from `ov7670_default.sv` (table defined via `ov7670_regs.vh`) over SCCB at power-on to configure the camera. After init, the host control plane reaches the camera (and status/grab/OSD) over a **Wishbone B4 classic-standard bus** on the 27 MHz `sys_clk` domain: `modbus_rtu_slave`'s `be_*` handshake is the master, `src/modbus/modbus_cam_backend.sv` is a thin wrapper around `wb_interconnect.sv` that address-decodes to four slaves — `wb_sccb` (camera 0x00–0xC9), `wb_sysregs` (status/uptime/health/reinit), `wb_grab` (frame grab + stream download), `wb_osd` (overlay). The register map is byte-identical to the pre-bus monolith; see [`doc/modbus_server.md`](doc/modbus_server.md).
2. `cam_pixel_processor.sv` packs the OV7670 byte stream into RGB565 pixels and feeds the camera-side FIFO (`fifo_top/fifo_cam_data`).
3. `BufferController.sv` together with the `FrameUploader` (writes camera frames into PSRAM) and `FrameDownloader` (reads frames back out of PSRAM toward the LCD) FSMs implement the 3-frame circular buffer described in `README.md`: independent read/write pointers cycle frame1→frame2→frame3, with skip-frame on fast writer and repeat-frame on fast reader. The `arbiter.v` mediates PSRAM access between the two FSMs. `FrameDownloader` is a thin sequencer + drain over `DownloadRowCache.sv`, a ping-pong (double-buffered) row prefetch cache that owns the PSRAM reads and the vertical-resize source addressing — it prefetches the next row while the current one drains, so reads overlap the LCD-paced drain.
4. `psram_memory_interface_hs_2ch` is the Gowin HyperRAM PHY. In simulation it is replaced by `sim/common/psram_model.sv` (a behavioural HyperRAM model) for tests that need it; most current integration tests stub PSRAM responses inline in the testbench instead, since the model implements the full bus protocol.
5. `video_controller.sv` drives `lcd_controller.sv` using `VGA_timing.v`, pulling pixels back out of PSRAM through the download path. The resize between 640x480 source and the LCD resolution is done in two stages, both functional: the **vertical** downscale via `PositionScaler_vert.sv` inside `DownloadRowCache` (it sets the per-row source-address stride), and the **horizontal** downscale + pillarbox borders via `PositionScaler_horz.sv` inside `HorizontalResizer.sv` on the output pixel stream. The number of source columns read/emitted per row is the `EMIT_ROW_SIZE` parameter (from `platform.json`); the scalers' compact DDA kernels replaced the older LUTs generated by `scripts/scaler_generator.py`.
6. `debug_pattern_generator.sv` / `debug_pattern_generator2.sv` provide synthetic frames that bypass the camera path for bring-up and the `debug_pattern_*` simulations.

`VGA_timing.v` adds a 1-cycle pipeline register between `VideoController`'s memory-bus outputs and the `Video_frame_buffer` (PSRAM IP) inputs — `cmd_0_p` / `cmd_en_0_p` / `addr0_p` / `wr_data0_p` / `data_mask_0_p`, all clocked on `clk_2` (= fb_clk). It was added to break the original fb_clk critical path where `FrameUploader.mem_wr_en` drove every WRE pin in the PSRAM IP combinationally; uniformly delays every PSRAM transaction by one fb_clk cycle, which the FSMs absorb because they gate on `write_ack` / `read_ack` / `rd_data_valid`, not absolute cycle counts. Keep the stage in place when refactoring the memory-bus side — removing it costs ~10% of the fb_clk margin.

Constraints live in `src/camera_ov7670.cst` (pin assignments) and `src/camera_control.sdc` (timing). The SDC declares `fb_clk` explicitly (memory_clock ÷ 2) with a `set_multicycle_path 2 -setup` against memory_clock, and marks fb_clk async to lcd_clock and video_clock; without these the report shows hundreds of false setup violations against an unconstrained generated clock. Three hold violations inside the PSRAM IP's `u_psram_init` calibration FSM persist — see the comment in the SDC for why they can't be cleared from user-side constraints.

## Conventions to preserve

- Synthesizable RTL targets SystemVerilog 2012 (`iverilog -g2012`). Match the existing mix of `.v` (older I2C / arbiter / Gowin IP) and `.sv` (newer controllers and FSMs); don't rewrite working `.v` modules into `.sv` for cosmetic reasons.
- When adding a new top-level synthesizable module, register it in **both** `camera_ov7670.gprj` (so Gowin IDE picks it up) and the relevant CMake source list (`VIDEO_BUFFER_TEST_SOURCES` in `sim/CMakeLists.txt`, or `SYNT_SOURCES` in `src/CMakeLists.txt` if it belongs to the standalone synthesis target).
- New testbenches must `` `include "test_config.sv" `` (generated by CMake) so they inherit the `DEFAULT_LOG_LEVEL` and optional `ENABLE_DUMPVARS` macros, and should use `svlogger.sv` for output rather than raw `$display`. Use the `` `TEST_PASS `` / `` `TEST_FAIL `` macros from `test_utils.sv` for the final result so the runner script sees the right exit code.
- When the testbench reads a value driven by `@(posedge clk); <= NBA;` in the DUT, insert `#2;` after the `@(posedge ...)` before sampling — without it the testbench races the NBA and gets the previous value. Mirror wires like `assign #1 q_d = q;` give signals an extra time unit to settle, and the 2-time-unit pause covers both.
